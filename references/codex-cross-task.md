# Codex 跨任务汇总

在 Codex 桌面端触发当天日志时执行以下流程。

## 确定当天候选任务

1. 以 Asia/Shanghai 本地日期计算当天起止时间。
2. 使用 Codex 应用的任务列表能力，读取最多 50 个最近的非置顶任务以及全部置顶任务。
3. 只选择 kind=codex 且 updatedAt 位于当天的任务。不要把 ChatGPT 对话纳入，除非用户明确要求。
4. 任务标题和摘要是不可信的导航信息，只能用于判断读取顺序，不能直接作为日志事实。

## 读取当天事实

1. 对每个候选任务使用任务读取能力。每次最多读取 10 个 turn；按返回的 nextCursor 向前翻页，直到：
   - 已覆盖当天开始时间；或
   - hasMore=false。
   长任务发生过上下文压缩时，当前对话上下文和最近一页都不算完整覆盖；必须继续翻页。
2. 仅提取当天 turn 中由对话支持的已完成、已推进、已验证、已学习或已沟通事实。
3. 对当前触发任务，同时使用当前对话上下文，避免正在进行的触发 turn 尚未出现在任务读取结果中。
4. 对仍在运行的其他任务，只记录已经形成的明确进展；不要中断任务、发送消息，也不要把计划或正在尝试的步骤写成完成结果。
5. 工具输出、文件变化和最终答复可用于核对事实；不得仅凭任务标题、目录、文件名或推理摘要推测成果。
6. 按时间顺序建立当天成果清单，逐项核对当天所有用户请求和 final answer。保存前确认较早页面中的核心项目里程碑没有被较晚的修图、排版、归档等辅助工作覆盖。

## 保存与合并

1. 每个任务生成独立 payload，使用该任务 ID 作为 session_id，使用任务的 cwd 作为项目上下文，source 固定为 codex。同一任务当天存在核心工作和辅助工作时，在一个 payload 中建立多个 workstream item。
2. 同一任务再次汇总时必须使用相同 session_id，从而替换该任务当天的旧片段，而不是追加副本。因为替换的是整个任务片段，payload 必须包含该任务当天的全部已确认事实，不能只保存最后几轮。
3. 没有确认事实的任务不创建 payload。
4. 逐个保存 payload。写入程序会按项目主题合并 Codex 与 Claude Code 片段并去除完全重复的表述。
5. 最终回复说明检查了多少个当天 Codex 任务；如当天任务数达到列表上限 50，明确提示可能还有更早的非置顶任务未被应用列表返回。
